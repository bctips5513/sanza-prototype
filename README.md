# 山座同定 精度検証プロトタイプ

指定した地点から見える稜線シルエットを国土地理院の標高タイルから計算し、実際の写真と重ねて精度を確かめるための静的 Web アプリです（AR による山名同定は対象外）。

## 使い方

1. **地点**：地図をタップ（マーカーはドラッグ可）、緯度経度を入力、または「現在地」。目の高さを設定して「稜線を計算」。
2. **パノラマ**：360° の稜線（手前の尾根ほど濃く表示）と見える山頂。山頂・稜線をタップすると距離・標高・仰角などを表示。稜線と山頂の CSV を出力できます。
3. **写真**：写真を選ぶと EXIF の位置・35mm 換算焦点距離・撮影方位から初期値を設定（位置があればその地点で自動計算）。
   - 自動合わせ：稜線の計算が終わると、写真の「空と山の境目」と計算した稜線が最もよく重なる方位・仰角・傾き・画角を全周から自動で探します（2〜4秒）。信頼度が低いときは適用せず、上位3候補をボタンで試せます。
   - 稜線を動かす：ドラッグで方位・仰角、ピンチで倍率。下のスライダー・ボタンで微調整。
   - 2点合わせ：写真上の既知の山頂を 2 つタップ → 対応する山を選ぶと、方位・仰角・傾き・画角を自動で合わせます。1 点目を選んだ時点で方位・仰角だけ先に合わせるので、2 点目の候補は写真上で近い順に並びます。3 点目以降は合わせに使わず、残差（px・度）を表示します。
4. **AR（試作）**（`ar.html`、設定タブにリンク）：カメラ映像に稜線と山名を重ねます。
   - 開始すると現在地で稜線を計算し、まずコンパス（持ち方・磁気偏角を補正）の向きで重ねます（±10°ほどずれる）。
   - 自動で始まる合わせ（既定で入）：コンパスで表示中に、稜線が映る向きで少し止まると、裏で自動合わせを走らせます（画面は止めません）。信頼度「高」で、センサーの仰角から 1.5° 以内・コンパスから 15° 以内の答えが 2 回続けて同じになったときだけ使います。
   - 「自動合わせ」ボタン：映像のコマを止め、センサーの向きの近く（方位 ±20°、合わせ済みなら ±10°。仰角・傾き ±3°）だけを探します（Mac で 0.2 秒前後）。画角がまだ測れていないカメラ・ズームでは焦点距離も ±25% 振り、その値を仮の画角にします。
   - 画角・傾きの測定（第2段階、既定で入）：合わせた後、向きを変えて止めたコマ（最大 4 枚）をため、向きの差が横の画角の 1/4 以上ある 2 コマ以上がそろうと、全コマ共通の補正（方位・仰角・傾き）と焦点距離を同時に求めます（`src/ar/calibrate.ts`）。コマ同士の向きの差はジャイロで分かっているので、1 コマでは傾きとつり合ってしまう画角がはっきり決まります。画角は測定値（直近 5 回）の中央値をカメラ・ズームごとに記憶します。「…」に診断表示（ズームの方式・公称値との差・測定値）。
   - 手動：止めた画面・ライブのどちらでも、1本指ドラッグ＝方位・仰角、2本指＝拡大縮小（画角）とひねり（傾き）。「微調整」で 0.1° ずつ。画角はカメラ・ズームごとに記憶します。
   - 合わせた後は「alpha（ジャイロ）から求めた方位＋補正」で表示するので、カメラを動かしても稜線が付いてきます。仰角・傾きのくせは持ち方ごとに記憶します。
   - 表示：いちばん奥の稜線（赤）と、手前の尾根の輪郭線（ピンク）を描きます。輪郭線は稜線の計算のついでに方位ごとに「そこで地形が手前と奥に分かれる点」を拾い、隣の方位どうしでつないだもの（`src/skyline/silhouette.ts`）。短い線・奥との距離の差が小さい線（同じ斜面の段差）・1 km より手前の線（山頂では足元の岩の陰になりやすい）は捨てます。「…」で稜線の太さ・濃さ・黒い縁、手前の線の量・太さを変えられます。
   - 山名：山頂のすぐ上に「山名 標高」を出し（重なれば少しずつ上、上が詰まれば下）、置けない山は印だけにします。有名な山（日本百名山・二百名山・三百名山・信州百名山。`src/peaks/famous.json`）を優先し、3 km より遠い山は「自分より高い山までの距離が、観測点からの距離の 4%（少なめ 8%・多め 2%）以上ある山」＝周りの主峰だけを出します。標高は一覧の値 → OSM の ele → 標高タイルの順。
   - 追従補正（既定で入）：カメラを止めている間、2.5 秒ごとに映像のコマで狭く（±2°）合わせ直し、信頼度が高くずれが小さいときだけ方位・仰角を半分ずつ直します（ジャイロのずれ対策。傾きは第2段階に任せる）。
5. **センサー検証**（`sensor.html`）：コンパス・ジャイロの精度を測るページ。横持ちのコンパスは持ち方（重力から判定）で補正し、磁気偏角（地理院の近似式）を補正した真北基準で誤差を出します。
6. **設定**：大気差係数 k、地球半径、距離帯ごとのタイル（ズーム）、多層稜線の距離帯、名前なし山頂の表示などを変更できます。

## 計算方法

- **標高**：地理院標高タイル（PNG）。`x = R·65536 + G·256 + B`、`x < 2²³ → x·0.01 m`、`x = 2²³ → 無効値`、それ以外 `(x − 2²⁴)·0.01 m`。ブラウザの色管理の影響を避けるため、Canvas を使わず純 JS（fast-png）でデコードしています。画素中心の値として双線形補間します。
- **距離帯（初期値）**：0〜3 km DEM5A z15（無効値は z14 にフォールバック）／3〜15 km z14（DEM10B）／15〜40 km z13／40〜100 km z12。
- **観測高**：DEM の地表標高（DEM5A 優先）＋目の高さ。GPS 高度は使いません。
- **稜線**：方位 0.1° 刻みに GRS80 楕円体の測地線に沿ってレイを飛ばし、距離帯の画素サイズ × 0.8 間隔でサンプリング。見かけの仰角は `atan((h − h観測 − d²/(2R)·(1−k)) / d)`（R = 6,371 km、k = 0.13）。
- **手前の尾根**：距離 2 / 5 / 10 / 20 / 40 / 100 km 以内の地形だけで求めた稜線を重ねて描きます。
- **山頂**：OSM の `natural=peak` を Overpass API で取得し、1° 格子ごとに IndexedDB へ 30 日キャッシュ。山頂ごとに専用のレイを飛ばし、手前の地形の最大仰角と比べて見通しを判定します（許容値 0.02°）。
- **写真**：ピンホールカメラモデル（主点は画像中心、歪みなし）。35 mm 換算焦点距離は対角 43.27 mm 基準で画素焦点距離に換算します。

## 写真の扱い

- 読み込んだ写真はブラウザ内でのみ処理し、外部へ送信しません。本番ビルドには CSP を埋め込み、通信先を地理院タイル・地理院標高 API・Overpass API に限定しています。
- テスト用の写真は `test-photos/` に置いてください（`.gitignore` 済み）。

## 開発

```bash
npm install
npm run dev          # http://localhost:5173/sanza-prototype/
npm test             # 単体テスト
npm run test:online  # 地理院サーバを使う検証テスト
npm run test:photos  # test-photos/ の実写真で自動合わせを評価（macOS の sips を使用。正解は test-photos/truth.json）
npx vitest run --config vitest.photos.config.ts tests/photos/calibrate.test.ts --silent=false  # AR の画角測定の評価
npx vitest run --config vitest.photos.config.ts tests/photos/silhouette.test.ts --silent=false  # 手前の尾根の輪郭線を写真に重ねた画像を .cache に書き出す
node scripts/build-famous-peaks.mjs  # 有名な山の一覧（src/peaks/famous.json）を作り直す（Wikidata・Wikipedia・Overpass を使用）
npm run build
```

`main` に push すると GitHub Actions でテスト・ビルドし、GitHub Pages に公開します。
